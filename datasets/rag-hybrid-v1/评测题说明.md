# Hybrid 检索评测题 v1

固定语料仅为 corpus/README.md 和 corpus/API.md。题目按文档表述标注，不代表对实际运行行为的验证。无答案仅针对这两份语料。

共 40 题：32 题有答案、8 题无答案；dev 30 题用于调参，test 10 题用于最终验证，不应根据 test 的失败反复调参。

## 使用

1. 新建独立评测知识库，仅上传 corpus 中两份文档，保持分块参数固定。不要上传本题库、manifest 或本说明，避免答案泄漏。
2. 记录真实 tenantId、knowledgeBaseId、分块参数，并填入 questions.jsonl 的绑定字段。
3. 依据 evidence 原文人工确认相关 Chunk ID，再填写 relevantChunkIds；多处依据的问题需覆盖各处。不要仅把当前检索前五条当作正确标签。无答案题保持空数组。
4. 已新增 `scripts/rag/hybrid-eval.mjs`：`prepare` 核对语料快照、分块参数及真实分块，按依据原文精确关联 Chunk；`evaluate dev` 通过实际 `RagService.search(..., 'hybrid')` 评测 30 道调参题。绑定与报告写入被 Git 忽略的 `reports/rag-baseline/hybrid-v1/`，不把真实租户和知识库绑定写入公开题库。原有 `baseline.mjs` 是 Dense 评测脚本，不要直接拿它代表 Hybrid 效果。

## 运行方式

在项目根目录执行：

```powershell
node --env-file=.env scripts/rag/hybrid-eval.mjs prepare
node --env-file=.env scripts/rag/hybrid-eval.mjs evaluate dev
```

无需启动后端 HTTP 服务，但 MySQL、Milvus 和 embedding API 必须可用。脚本只读知识库，不改动已上传数据；仅接受唯一名称 `RAG 评测 v1`，有重名时会停止。评测会产生 embedding API 调用。只有确定方案后，才运行 `evaluate test`；不要根据保留题成绩反复调参。

2026-11-23 首轮 dev：16 个分块、30 道题（24 道有答案、6 道无答案），调用失败 0；Hit@5 为 23/24（95.83%），MRR@5 为 0.9028，全部依据覆盖率为 23/24，P95 总检索耗时 348.24ms。此耗时包含脚本中的知识库查询、embedding 与 Milvus 检索，不含 Agent 推理或浏览器网络时间，来自单次顺序运行而非并发压测。

漏召回题：`hybrid-006`，问题为“这个项目使用的 embedding 模型及向量维度分别是什么？”。6 道无答案题均有返回片段；这不是答案幻觉率，当前没有评测生成回答和拒答。10 道 test 保留题尚未运行。这是小规模项目文档语料的开发基线，不能作为独立测试集或生产准确率。

后续无答案测试应禁用联网搜索并只使用本语料；返回相关片段不等于已经具备答案依据。若语料变化，重新核对标签并建立新版本。
