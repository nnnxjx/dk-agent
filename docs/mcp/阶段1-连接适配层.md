# 阶段 1：单 Server 连接适配层（纯 HTTP）

## 1. 目标

只实现“连接、初始化、列工具、调用工具、关闭”，暂时不接数据库和前端。

## 2. 交付

- `src/mcp/mcp-transport.factory.ts`
  - `createStreamableHttpTransport`：每次新建 transport，已启动的不复用
  - `createMcpClient`：先校验配置，再建 Client
  - `connectMcpClient`：建连加超时，失败尽力释放
  - `withTimeout`：超时统一抛 `MCP_TIMEOUT`
- `src/mcp/mcp-result.normalizer.ts`
  - text 拼接；image/audio/resource 转占位描述，不塞二进制进 prompt
  - `structuredContent` 原样透传；超长截断并标记 `truncated`
- `src/mcp/mcp-connection.manager.ts`
  - `testConnection`：cursor 分页，上限 200，`inputSchema` 透传
  - `callTool`：返回归一化对象，远端 `isError` 抛错
  - `getLeakedConnections()`：close 失败计数，用于测试发现泄漏

## 3. 连接策略

- 仅 HTTPS 或 localhost，鉴权头白名单 `authorization/x-api-key`
- 建连默认 10s，调用默认 60s
- 每次新建 Client + Transport，用完 close，阶段 1 不做缓存

## 4. 验证

```bash
npx jest src/mcp --runInBand
npx tsc --noEmit -p tsconfig.json
npx ts-node --transpile-only scripts/mcp/test-http-server.ts
MCP_TEST_URL=http://localhost:3100/mcp npx ts-node --transpile-only scripts/mcp/test-http-connection.ts
```

预期：`echo/fail/big` 三个工具可见，`big` 截断，`fail` 与不存在的工具抛错，泄漏为 0。

## 5. 给阶段 2 的接口

- `testConnection(config)` -> `{ tools: [{ name, description, inputSchema }], durationMs, truncated }`
- `callTool(config, toolName, args)` -> `{ text, isError, truncated, blockCount, structuredContent }`
- 远端 `isError` 已转为异常，阶段 2 适配 LangChain 时直接透出错误文本即可
