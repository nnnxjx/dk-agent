# 第四步首轮复核记录

本文件记录本轮 Agent 对保存结果的抽查，不等同于独立人工审核。统计规则与题库在运行前固定；下列发现不回改本轮分数。

## 检索：严格来源匹配可能漏算等价证据

- `project-053` Top3：标准引用指向 `api.md` 的 `POST /api/v1/knowledge-bases/:id/documents`，最终结果的 `overview.md` 实际也包含同一个接口。严格来源条件不匹配，记为“标注证据丢失”，但不能据此说没有找到可回答资料。
- `project-104` Top3/5/10：标准缓存键证据指向 `pool.md`，最终 `management.md` 中也有 `tenantId + serverId + configVersion`。存在同样的来源标注不完备问题。
- `project-080` Top3/5/10：标注的“禁用/删除/更新配置时 invalidateServer 即刻失效”已在各库候选中，最终 Top10 没有这段原文。属于真实的标注片段排序后丢失，但最终其他片段可能部分表达相近事实，需要另外做语义证据审核。
- `project-105`：组合题对“一次性测试并 close”与“test/refresh/探活不走池”分别标注证据；后者未进入最终 Top10，完整证据指标未通过。不能仅因某一片段提到“一次性”就默认已经支持全部操作范围。

后续应在不依赖某一种算法排名的前提下，审核完整冻结语料，标注同一必要事实的所有等价支持来源。替代证据应建成 OR 组，不同必要事实之间用 AND 组合。不能简单把两处等价来源加入当前 evidence 数组，否则会错误地要求两个来源都被找回。

本轮保留来源严格的指标，明确将其称为“标注证据覆盖”，不把它当作穷尽语义证据的召回率。后续标签版本变化应单独保留旧报告，并用相同新标签对所有待比较算法重新统计。

## 问答：保留自动评审与引文核验的差异

- `project-022` 与 `project-029` 的自动评审认为回答有依据，但程序对部分引文无法做连续原文匹配，导致忠实度扣分。应查看单题 `rawJudgment` 和 `judgment` 的差异，而非直接认定模型编造。
- `project-027` 的核心定义正确，评审对额外的“不同知识库 localScore 不可比较”陈述判为实际上下文不支持。核心正确率与忠实度是不同指标，不应混为“所有陈述都正确”。

全量需复核的回答列表由 [首轮结果报告](rag-step4-results.md) 从保存的评分自动生成，包含错误、漏要点和未支持陈述。报告中的评审 reason 是模型原始说明，可能与程序引文核验后的标签不同。
